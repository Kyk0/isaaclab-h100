Isaac Lab on H100

Train headless. Render elsewhere.

NVIDIA lists GPUs without RT cores, like the H100, as unsupported for Isaac Sim. That is about rendering. Training does not render: the physics runs on CUDA, so headless RL training works on an H100. Here is exactly what we ran and which errors you can ignore.

The 30-second answer

Isaac Sim on H100: no RT cores, and that's fine for training

✓ Training works

Headless RL training

PhysX runs on CUDA. Use --headless, skip cameras and --video, and train thousands of environments in parallel.

✕ Rendering doesn't

No RT cores, often no Vulkan

The RTX renderer needs RT cores. On servers with the compute-only driver there is no Vulkan or EGL either, so nothing renders at all.

→ The fix

Render on an RTX machine

Train on the H100, copy the checkpoint with its config.yaml, and make videos on any machine with an RTX GPU.

NVIDIA's Isaac Sim 5.1 requirements: GPUs without RT Cores (A100, H100) are not supported. That line is about the renderer. Headless training never calls it.

Startup log

Seeing "No device could be created"? You're probably fine

At startup Isaac Sim tries to create a Vulkan device for the renderer, logs a wall of red, and carries on without it. These are the exact lines from our H100 logs:

[Error] [gpu.foundation.plugin] No device could be created. Some known system issues:
[Error] [gpu.foundation.plugin] The chosen activeGpu index 0 is higher than the available GPUs.
[Error] [gpu.foundation.plugin] Invalid getDeviceInfo parameters.
[Error] [omni.gpu_foundation_factory.plugin] Failed to create any GPU devices, including an attempt with compatibility mode.
[Error] [omni.kit.renderer.plugin] GPU Foundation is not initialized!
[Error] [omni.kit.renderer.plugin] Graphics plugins not available
[Error] [omni.ui] Failed to create texture GPU data! [512 x 64, 1 mips]
[Warning] [omni.physx.foundation.plugin] PhysXFoundation: Unable to get IGpuFoundation, GpuDevices or Graphics!
| Driver Version: 0             | Graphics API: Vulkan
Could not load the dynamic library ... libXt.so.6: cannot open shared object file
sh: 1: zenity: not found

The rule: if the log then prints Environment device : cuda:0 and starts Learning iteration blocks, every red line above it was harmless.

Every message with its cause and fix, including the few that are real problems: troubleshooting.

The hidden cause

Nothing renders at all? Check the driver package

Many data-center servers use the compute-only NVIDIA driver (nvidia-headless-*-server). It leaves out the graphics libraries, so there is no Vulkan and no EGL: not even MuJoCo can render. Same H100, same software, only the driver package differs:

Training works with either. If you also want MuJoCo rendering on the server, ask your admin for the full driver (nvidia-driver-*-open). scripts/collect_env.sh tells you which one you have.

Quickstart

Train Isaac Lab on an H100 in three steps

Check your machine

bash
bash scripts/collect_env.sh   # GPU, driver, versions, Vulkan

Install Isaac Lab 2.x

The official conda + pip install, nothing H100-specific: install notes.

Train the G1 walking task, headless

bash
cd <ISAACLAB_DIR>
./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/train.py \
  --task Isaac-Velocity-Flat-G1-v0 --headless --num_envs 4096 --max_iterations 20

Look for Environment device : cuda:0. Drop --max_iterations to train the full 1500 iterations; that is the policy in the video above. More: SONIC fine-tune and flags.

Ready to load

Pre-converted Unitree G1 USD

The Unitree G1 exactly as SONIC uses it, already converted from URDF. Download it if you train SONIC, or if URDF conversion fails on your server.

bash
bash scripts/download_usd.sh   # Hugging Face download, sha256 check, unpacks to usd/g1_sonic/
python scripts/convert_robot.py --verify usd/g1_sonic/g1_sonic.usd --base_height 0.76

Hosted at huggingface.co/datasets/Kyry10/unitree-g1-usd. License: Unitree meshes (BSD 3-Clause), URDF edits by BeyondMimic (MIT) and NVIDIA (Apache 2.0). Converting your own robot: robot USD guide.

FAQ

Questions people ask

Does this work on an A100?

It should: the A100 has no RT cores either, so it should behave just like the H100. We have not tested it yet. If you run Isaac Lab on an A100 (or H200, B200, L40S), please send a GPU report with the output of scripts/collect_env.sh; every report goes into the table, with credit.

What about Isaac Lab 3.0?

Isaac Lab 3.0 came out on 2026-10-20. Its default install runs without Isaac Sim, on the Newton physics backend, and its docs say headless Newton simulation does not require RTX hardware. Many projects, SONIC included, are built on Isaac Lab 2.x and will stay there for a while; this guide is for them. A 3.x section is planned for v0.3.

Can I use mjlab instead?

Yes. mjlab puts Isaac Lab's API on top of MuJoCo Warp, with no Isaac Sim at all. We train motion-tracking policies with it on a compute-only H100, and the log is perfectly clean. Good choice if you don't need USD scenes, RTX cameras or PhysX.

Docker, Apptainer or Slurm?

Isaac Lab ships Docker images and a cluster guide for Singularity/Apptainer. The same rule applies inside containers: training needs only CUDA. The repo includes a Slurm starting template; containers and Slurm get their own section in v0.3. See alternatives.

Can I render on an H100 with the full driver?

With the full driver, Isaac Sim does find a Vulkan device on the H100 and the startup log is clean. Rendering images is still outside what NVIDIA supports, and other users report crashes or noisy images with cameras on H100 and A100. For videos and camera data, use an RTX GPU.
